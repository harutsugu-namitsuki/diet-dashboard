## 📁 プロジェクト構造 (Monorepo)

本プロジェクトは**「モノレポ（Monorepo）」**という構成を採用しています。
通常、Webアプリとスマホアプリは「別々のプロジェクト」としてバラバラに管理されますが、モノレポでは**「1つの巨大なプロジェクトフォルダ（箱）の中に、複数のアプリを同居させる」**ことができます。これにより、目標体重やカロリー計算式といった「共通の部品」を1箇所に作るだけで、すべてのアプリで一緒に使い回せるのが最大のメリットです。

* 📱 **`android_app/`**: スマホで毎日手軽に食事や体重を記録するためのモバイルファーストなアプリ。
* 💻 **`web_app/`**: PCやタブレットで全体を俯瞰するためのダッシュボードアプリ。
* ⚙️ **`common/`**: `web_app` と `android_app` の両方で使い回す「共通の部品（目標体重の数値や、カロリー計算のロジックなど）」を置いておくフォルダ。

### ルート階層の管理ファイル群
一番上の階層（ルート）には、プロジェクト全体を管理するための設定ファイルやドキュメントが置かれています。
* **`package.json` / `package-lock.json`**: アプリ全体の「戸籍謄本」や「全体マップ」のような存在です。「この大きな箱の中には、web_app と android_app と common が同居して連携しているよ」ということをシステムに教える役割を持っています。
* **`CHANGELOG.md`**: アプリのアップデート履歴（いつ・何の機能を追加したか）を記録しているファイルです。
* **`CONTRIBUTING.md`**: 今後開発に参加する人向けのルールブックです。
* **`input/`**: 最初の要件定義の際に使った分析結果やメモ（旧 `diet_status_summary.md` 等）をアーカイブしているフォルダです。

## 💻 開発環境の立ち上げ方 (How to Run)

ローカル（お手元のパソコン）でアプリを起動して開発・確認を行うための手順です。
※ 以前のバージョンと異なり、モノレポ構成になったため起動方法が変わっています。

```bash
# 1. プロジェクトのルートフォルダに移動（すでにいる場合は不要）
cd path/to/diet-dashboard

# 2. 必要なライブラリのインストール（必須）
# ※ これにより `common/` フォルダのロジックが各アプリから読めるようになります。
npm install

# 3. アプリの立ち上げ（用途に応じてどちらか）
## 📱 Androidアプリ版UIを起動する場合:
cd android_app
npm run dev

## 💻 Webダッシュボード版を起動する場合:
cd web_app
npm run dev
```

起動後、表示される `http://localhost:5173/` にブラウザでアクセスしてください。

## 💡 備考: `package.json` が参照されるタイミングについて
プロジェクトのルートや各アプリにある `package.json` は、主に以下の3つのタイミングで裏側のシステム（npm）に読まれます。

1. **`npm install` を実行した時**
   システムは `package.json` を見て、「なるほど、この箱の中には `web_app` と `android_app` と `common` が同居しているんだな。お互いのコードを直接呼び出せるように、裏でリンクを繋いでおこう！」と自動で準備をしてくれます（これがモノレポ連携のキモです）。
2. **`npm run dev` などを実行した時**
   システムは「動かすって具体的に何のプログラムを起動すればいいんだっけ？」と `package.json` 内の辞書を読みに行き、正しくサーバーを立ち上げます。
3. **世の中に公開されるとき（GitHubアップロード時）**
   GitHub側のコンピューターが、「このアプリを動かすには何の部品が必要なんだ？」と一番最初に確認するのがこのファイルです。
